swag audit

2026-10-23vetr0s/swag @ bc910b7Audit

swag is small, tested, and mostly well-shaped. Every package passes go test and go test -race, and the pipeline matches the spec. One class of bug is serious enough to fix before anything else. The check that protects the output directory compares paths as plain text. On macOS that lets swag build --out Content delete the real content/ directory, and the same check lets --out .git or --out swag.conf destroy those. All three were reproduced. The fix is to compare resolved, case-folded paths, and to refuse to replace anything that is not an earlier swag output.

Scope

Audited: all 13 packages under internal/, main.go, the tests, the fixture sites, go.mod, and README.md as the spec. Excluded: the generated golden trees under testdata/sites/*/expected/. Windows behaviour was not run. Performance was not measured beyond the 130 ms build already observed on vetr0s.dev.

What's solid

  • The standard library is the only dependency, and go list -m all prints one line. go vet and gofmt are clean. The race detector finds nothing.
  • A failed build never touches the existing output. Every error, including a broken link, returns before the swap. The failure-safety test covers six failure kinds.
  • The render worker pool writes results by job index, so parallelism never changes the output. WaitDelay keeps a stray grandchild from stalling a timeout.
  • The front matter, config and tokenizer parsers follow §4 and §5.4 closely, and their table tests cover BOM, CRLF and the first-colon split.
  • Generate is 155 lines, but it is a straight run of the §10 phases. Splitting it would add a state struct and buy nothing.
  • Diagnostics point at real files and lines, including template errors inside layouts and partials.

Findings

Ordered by consequence. "Reproduced" means the behaviour was run against a scratch copy of a fixture site, not just read.

Documentation drift

The repo is public now, and README.md is still the working spec. Its top says it is temporary and it has no install instructions. Inside the spec, these statements no longer match the code:

  • §14 says the module path is TBD and shows cli.Run(os.Args[1:], ...). The module is github.com/vetr0s/swag, and main.go:13 passes the version first.
  • §19 still lists the license and module path as open. Both are decided.
  • §2 asks CI or a test to check go list -m all. main_test.go checks for require lines instead, and there is no CI.
  • §12.5 says local builds report the VCS revision. Go now stamps a pseudo-version, which is what swag version prints.
  • §11 says only a trailing slash resolves to index.html. The checker also accepts /notes when notes/index.html exists.
  • §12.2 does not say --out is relative to the site root, or that the summary prints a cwd-relative path.
  • §5.4 promises the body's line number is used to offset renderer errors. Nothing uses it.
  • §14 puts passthrough rendering in render. It lives in build, and that is the cheaper place.
  • The sample config in §4.1 names "Nick Tebbs".

Recommended order of work

  • Make CheckOut safe: resolve symlinks and compare case-insensitively. Refuse an existing output path unless it is a directory holding an index.html, which every swag build writes. Test it on real temp directories.
  • Make the swap recoverable: rename the old output aside, rename the new one in, then delete the old one. Clean up the temp directory on SIGINT and SIGTERM in swag build.
  • Restore determinism. Parse partials in sorted order and compare collision keys case-folded.
  • Fix the CLI contract. Handle -h, reject extra arguments with exit 2, and require the -C directory to exist.
  • Fix serve: take the baseline before the first build, cache whole render results keyed on source and drafts too, and test rebuild directly.
  • Fix the smaller defects: the linkcheck quote scan, timeout ordering, and the slug.
  • Remove the drifted copies and the dead BodyLine. Add layout tests.
  • Resolve the documentation drift as part of the README work.
